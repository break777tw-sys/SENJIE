# 台南場地供給問句：本機可複驗案例

2026-11-19。本輪限既有 SENJIE 本機開發；沒有 Google、雲端模型或付費 API 呼叫，沒有部署。這是 G5 自然語言找人的一個限定案例，尚未完成一般複合條件查詢或真實 Google 最新資料驗收。

## 修正與預期結果

原本關鍵字「台南 場地」會跨供給、需求與談話搜尋，9 位虛構人物中列出 8 位，包含只在需求欄尋找場地的 DEM-001；完整問句則原本找不到人。現在輸入「台南誰能提供場地」，網站只列以下 2 位，逐筆顯示原始地區、供給欄位、確認層級、來源編號及人物版本，可開啟原人物資料核對。

| 人物編號 | 版本 | 原地區欄位 | 原「能提供什麼」欄位 |
| --- | --- | --- | --- |
| SUP-001 | 2 | 台南 | 可提供台南活動場地 |
| SUP-002 | 3 | 臺南市 | 台南活動空間出租 |

固定資料為 [people-search.json](../../tests/fixtures/people-search.json)，全部為公開虛構紀錄。需求方、其他城市、否定供給、待確認、談話推測、推論欄位與確認回條過期的紀錄均不列入。分類及職稱不作供給證據。

`search.js` 使用確定的規則解析這個問句，支援台／臺、台南市、空白、問號以及已列測試的近似問法。不呼叫語言模型，也不宣稱理解任意自然語言。額外條件如「免費」或「有停車場」、其他城市或反向需求問句回覆尚未支援並清空結果，不偷偷忽略條件。一般姓名／關鍵字搜尋仍保留原行為，畫面明示會搜尋供給、需求與談話。

只使用已確認人物的地區與供給欄位；有逐欄回條時，值必須與目前欄位一致且標示使用者確認。舊紀錄沒有逐欄回條時會明列「人物紀錄已確認；無逐欄回條」，不臆造來源編號或版本。相同人物只取可判定的最新版本，同版本內容矛盾則不列入。這是紀錄比對，未查場地實際地址、檔期或報價，亦不能推定人物所在地就是場地所在地。

## 複驗

在 SENJIE 根目錄執行，使用 Node.js，無外部套件：

```sh
node --test tests/people-search.test.js
node --test tests/*.test.js
node scripts/build.mjs
node experiments/people-search/server.mjs --port 8789
```

最後一個指令持續執行，開啟其回傳的本機網址。預設為 `http://127.0.0.1:8789/`，只限執行電腦；不是手機或公開入口。若連接埠已占用，先核對既有測試程序，或明確選用其他空閒埠。以 Ctrl+C 停止本次程序。

此唯讀外殼直接提供實際 index.html、CSS、app.js、search.js、transport.js，只將 model.js 的 demoCards 換成 9 位固定虛構資料，保留原 model 函式；不改 Google bridge、不連外、不持久寫入。`/fixture.json` 可讀回相同測試資料。一般正式資料仍由原 transport 讀入，本輪沒有 Google 端到端證據。
