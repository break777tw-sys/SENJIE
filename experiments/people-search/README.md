## 本輪修正

舊 21d4c7e 已部分通過基本供需獨驗，但以下三種原文仍會誤列，已先重現並新增回歸：

| 原文／人物條件 | 新結果 | 依據 |
| --- | --- | --- |
| 沒有辦法提供台南場地 | 排除 | 否定供給，不能只匹配「提供」 |
| 可提供台南場地；僅供內部使用 | 排除 | 內部限制跨分句仍有效 |
| 人物在台南；只能提供高雄場地 | 排除 | 人物地區不代替場地所在地 |
| 人物在高雄；可提供台南活動場地 | 可列入 | 明確供給原文指出台南場地 |

供給必須在已確認欄位中明確提到台南場地及提供／出租等供給行為。只有「可提供場地」加人物地區台南不足以確認；同一分句混合其他城市時保守不列入。沒有辦法／能力、內部使用限制、需求、轉介、推測及待確認不能當確定供給。這是有界規則，不宣稱涵蓋所有中文否定或任意地名句法。

## 問句與資料

- 「台南誰能提供場地」：18 位擴充資料列 6 位，依據只使用供給欄位；認識場合未確認不影響這個沒有場合條件的問句。
- 「上次在交流會認識、能提供台南的場地的人有哪些？」：列 SUP-001（版本2）及 SUP-CROSS-001（版本1），兩位都在 2026-11-10「秋季交流會」認識，且供給欄位明確提供台南場地；SUP-002 在較早交流會，故不列入。
- 原 [9 人資料](../../tests/fixtures/people-search.json)及基本問句回歸保留；新 [18 人擴充資料](../../tests/fixtures/people-search-context.json)包含三種誤薦、跨城市正例、不同／較早場合、待確認／過期場合回條、純需求及談話線索對照。

「上次」只指目前已載入、已確認且可核對的交流會認識紀錄中最近日期，先從全部人物判定，再篩供給與分類，不回退到有供給者的較早活動。畫面顯示實際日期、場合與此資料範圍。未載入紀錄與同名同日不同場次無法由目前資料辨別；不宣稱知道使用者所有活動。

本輪認識原文採可核對格式，例如「2026-11-10 在秋季交流會認識」，日期必須是真實日曆日期；以句號、分號或換行分隔紀錄。這是既有 notes 欄位的限定解析，不新增後端欄位。確認回條須對應目前 notes 值；缺日期／格式不明、最近日期有不同場合時回覆無法判定，不猜測。場合未確認、推論或回條過期者不作場合證據。

結果逐筆引用供給原文、認識日期與場合、確認層級、來源編號及人物版本；人物地區只作背景並清楚標示非場地依據。舊紀錄沒有逐欄回條時會明列紀錄確認層級，不臆造來源或版本。可開啟人物原資料對照。

規則支援兩組已列測試的近似問法；「免費」「停車場」等額外條件或未知城市明示尚未支援並清空結果，不悄悄忽略條件。姓名／一般關鍵字仍沿用原跨欄搜尋，畫面明示模式。未驗場地實際地址、檔期或報價。

## 複驗

在 SENJIE 根目錄執行，使用 Node.js，無外部套件：

```sh
node --test tests/people-search.test.js tests/people-search-context.test.js
node --test tests/*.test.js
node scripts/build.mjs
node experiments/people-search/server.mjs --port 8789
```

最後一個指令持續執行。開啟回傳的本機網址，預設 http://127.0.0.1:8789/，僅執行電腦可用，不是手機／公開入口。若埠被占用先核對既有測試程序，或選其他空閒埠；Ctrl+C 停止本次程序。
