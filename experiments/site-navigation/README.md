# SENJIE 總入口與名片模組：本機複驗

## 窄版片段定位修正與複驗

先前5c227cc在320／390px寬度，首頁點入或直接重載#cards都下捲486px，返回入口落在-405至-359px、導覽落在-343至-258px，因而看不到。這是本機Chrome實際讀取DOM位置，非DOM facsimile推算。

新版保留#cards與全部原路徑，只在700px以下處理畫面進入：用目前section在文件中的位置設定scroll-margin-top，避免瀏覽器較晚的片段定位跳過上方導覽；在導覽、load與pageshow後安排一次捲動復位。相同畫面的hash事件也處理；不監聽一般捲動、搜尋輸入或視窗resize來強制回頂，不改瀏覽器歷史或桌面定位規則。

Chrome的320×844與390×844實測，首頁點入、直接#cards重載、上一頁#home及下一頁#cards均scrollY=0；返回入口81–127px、導覽143–228px都在畫面內。390px另測四畫面切換、原複合問句仍2位，搜尋時scrollY=426，沒有被拉回頂端。窄版選單沿用原橫向可捲動形式。

解除viewport設定後，桌面1452px直接入口及前後導覽正常，窄版scroll-margin不生效（0px），返回入口仍可見。測試結束已恢復原瀏覽器尺寸；這是Mac mini Chrome指定viewport驗收，不是手機實機。

本輪新增4項邏輯回歸，涵蓋320／390進入、較晚load／pageshow／同route事件、前後導覽保留查詢、一般查詢不復位及桌面不發新捲動指令；DOM facsimile沒有真實布局，位置通過以Chrome實測另列。全套85項與建置通過，新固定版本仍待原獨立驗收者複驗，Google私站不部署。

## 啟動與路徑

在SENJIE根目錄使用Node.js，無外部套件：

```sh
node --test tests/site-navigation.test.js
node --test tests/*.test.js
node scripts/build.mjs
node experiments/people-search/server.mjs --port 8789
```

最後一個指令持續執行，開啟它回傳的本機網址。這個既有唯讀外殼提供原網站模組，只把示範資料換成20位固定虛構人物，沒有Google bridge、連外或持久寫入。根目錄靜態預覽也能顯示總入口，但使用原model的3位虛構資料，不能和20人fixture的搜尋結果混比。Ctrl+C停止本次程序；埠被占用先核對既有程序，或明確指定另一空閒埠。
